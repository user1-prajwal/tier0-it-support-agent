# MFA enrolment and recovery

## Enrol a new authenticator

Multi-factor authentication adds a verification step after the work-account password. Employees should enrol an approved authenticator before they need it for an urgent sign-in. Begin from the organization's official account security page using a trusted browser. Sign in with the work account and complete the existing verification step.

Choose the option to add an authenticator application. The page may display a QR code or a one-time setup key. Scan the QR code only inside the approved authenticator application. Do not photograph it, send it to another person, or store it in a shared document. The setup key is sensitive because it can be used to generate verification codes.

Enter the current code from the authenticator application when the enrolment page requests confirmation. Wait for the success message before closing the page. If the page offers recovery codes, save them in the approved password manager or another company-approved secure location. Do not keep recovery codes in an unprotected notes file or send them to a colleague.

After enrolment, test a fresh sign-in in a separate browser session. Confirm that the prompt is generated by a sign-in you initiated. If an unexpected approval request appears, deny it and report the event through the normal security support channel.

## Lost or replaced device

If a phone containing the authenticator is lost, replaced, or reset, use another previously enrolled verification method if one is available. Sign in to the official account security page and remove the unavailable device only after the replacement method has been successfully enrolled. If no alternate method is available, contact the IT helpdesk and request identity-verified account recovery.

Support staff may ask you to complete the organization's identity verification process. They must not ask you to disclose a password, one-time code, or recovery code. Do not accept help from an unsolicited caller who offers to bypass MFA. Do not approve a prompt merely because it appears repeatedly.

If the device was lost in a public place or may have been accessed by another person, report the loss promptly. Follow the device-security process and tell support whether the device was protected by a screen lock. Do not attempt to recover an authenticator database from an unknown website or unofficial application.

## Repeated or unexpected prompts

Repeated prompts can result from an application retrying an expired session, but an approval request that you did not initiate may indicate an attempted sign-in. Deny unexpected requests. Change the account password through the approved password reset process if compromise is suspected, and report the approximate time and prompt details to IT security.

When reporting a problem, include the application name, device type, approximate time, and the exact message shown. Remove any visible one-time code or recovery information from screenshots before sharing them. Never include the secret QR code or setup key in a support ticket.
