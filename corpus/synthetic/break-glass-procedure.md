# Break-glass procedure

## Purpose and eligibility

Emergency access exists for a severe operational or security event when normal privileged access cannot meet an urgent, documented need.

It is not a convenience route for delayed approvals or routine administration.

Only designated responders may request activation, and every use is subject to review after the event.

## Activation reference

The synthetic emergency policy identifier is POL-SEC-014.

The training vault label is EMBER-VAULT-2.

These identifiers are fictional and are included to support exact-token retrieval tests.

Responders must verify the current approved procedure in the restricted security repository before taking action in a real environment.

## Conditions for use

The incident commander must state the event, the system affected, the task that cannot wait, and why the normal route is unavailable.

A second authorized responder should confirm the request where the situation permits.

If the second confirmation cannot be obtained during an immediate threat, the reason must be recorded and reviewed as soon as practical.

## Credential custody

Emergency credentials are held in the approved secure vault and are not copied into tickets, chat messages, email, shell history, or personal notes.

A responder must access only the credential required for the approved task.

Credentials must not be shared with a person who is not an authorized responder.

## Session monitoring

The responder must record the start time, identity, incident reference, target, and intended action.

The session should be monitored where the platform supports it.

Perform only the minimum action needed to restore safe operation or contain the event, then end emergency access.

## Closure and rotation

After use, notify the security duty lead and arrange credential rotation according to the vault process.

Preserve the approved audit evidence and record any deviation from the normal approval sequence.

The incident commander assigns an independent reviewer who checks whether the access was justified and whether all required records exist.

## Review and misuse

Emergency access is not a substitute for normal access management.

Repeated use for ordinary work must be escalated as a control failure.

Any suspected exposure, unexplained access, or missing audit record must be reported through the security incident process immediately.
