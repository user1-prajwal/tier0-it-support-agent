# 0000: Phase 0 decisions (project skeleton)

Date: 2026-11-19. Status: accepted.

## Decisions

| Decision | Why | Rejected |
| --- | --- | --- |
| Develop in WSL2 (Ubuntu 24.04) | Matches the Linux containers and CI. The Makefile works as written | Native Windows with PowerShell |
| `venv` + `pip`; ranges in `pyproject.toml`, exact versions in two lockfiles | Reproducible installs. Runtime and dev dependencies stay separate. Only dependencies on the brief's allow-list | uv or poetry (not on the allow-list) |
| `pydantic-settings`, `SecretStr`, no default `DATABASE_URL`, provider is a `Literal` without `openai` | Missing config stops the app at startup. Passwords do not appear in logs. No OpenAI by construction | Defaults that guess a database |
| `HashEmbedder` uses `sha256`, behind an `Embedder` Protocol | Deterministic tests. The real embedder can be swapped in later. Python's `hash()` is randomised per process | Built-in `hash()`, a base class |
| `create_app()` factory, sync `def` endpoints, one router file per feature | Easy to test and debug. Matches the brief | `async` endpoints, a global app only |
| `pgvector/pgvector:0.8.2-pg16`, named volume, port bound to `127.0.0.1` | Pinned version. Data outlives the container. The database is not reachable from the network | Floating tag, bind mount, `5432:5432` |
| Healthcheck plus `docker compose up --wait` | A started container is not yet a database that accepts connections | Fixed sleeps |
| `CREATE EXTENSION vector` in Alembic migration `0001`; `env.py` reads `Settings` | Versioned and repeatable on every machine. No password in a committed file | Docker init script, `create_all` |
| `/health` (liveness) and `/health/ready` (readiness, 503 on database failure) | Liveness must not depend on the database. Readiness must | One endpoint for both |
| Dockerfile: `slim-bookworm`, runtime lockfile only, non-root uid 10001, exec-form `CMD`, Python-based `HEALTHCHECK` | Small image, less attack surface, clean shutdown, no extra packages | Alpine, running as root |
| CI: real Postgres service container, install from lockfile, `LLM_PROVIDER=fake`, `contents: read` only | Tests run on the same database as production. Identical dependency versions. No live model calls. Least privilege | Mocked database, fresh dependency resolve |

## Known deviations and open items

- `make lint` runs `ruff check` only; there is no format check yet.
- The Docker base image is pinned by tag, not by digest. Digest pinning is planned for Phase 5.
- Integration tests use the development database. Before the first test that writes rows (Phase 1), they need a separate test database.
- The test run prints an httpx deprecation warning from Starlette. It is not an error. Revisit when dependencies are re-pinned.
- Local ruff and CI ruff disagreed on import order. Fixed with an explicit `known-first-party = ["app"]`.
- `actions/setup-python` v6 was checked against its release list. The `actions/checkout` version was not verified.
