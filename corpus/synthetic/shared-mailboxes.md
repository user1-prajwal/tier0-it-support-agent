# Shared mailboxes

## Purpose and ownership

A shared mailbox allows an approved team to manage messages for a common business function.

It is not a replacement for an employee's personal mailbox.

Each shared mailbox has a named business owner who confirms membership and reviews whether access remains necessary.

## Requesting membership

Request access through the service portal and identify the mailbox, the work task, and the manager who can approve the need.

The mailbox owner reviews the request before support applies the permission.

Do not ask a teammate to forward all mailbox messages to a personal account as a shortcut.

## Training mailbox names

The synthetic examples in this guide are facilities.demo@demo.local and orders.demo@demo.local.

They are fictional identifiers used only for retrieval exercises.

In a real request, copy the exact mailbox address from the approved directory entry and verify it with the mailbox owner.

## Sending messages

When sending from a shared mailbox, check the From field before sending so recipients see the intended team identity.

Use the mailbox only for its approved business purpose.

Follow the organization's normal retention, privacy, and recordkeeping rules; a shared mailbox does not make a message less sensitive.

## Membership changes

The mailbox owner should request removal when a team member changes role or no longer needs access.

Temporary membership should have a review or expiry date.

If an employee leaves the organization, normal account offboarding controls apply and mailbox membership must be reviewed as part of that process.

## Troubleshooting

If the mailbox is missing from the mail application, confirm that the correct work account is signed in and allow time for a recently approved permission to apply.

If messages can be read but sending fails, report the exact behavior and whether the issue occurs in the web or desktop application.

Do not share mailbox passwords; shared mailbox access should be granted through individual identities.
